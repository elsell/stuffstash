# CLI complete print submission requests

`labels print ASSET_ID`, `printers test PRINTER_ID`, and `print-jobs reprint JOB_ID` support the complete print selection request through `--input FILE` or `--input -`. Exact JSON includes printer ID, expected media fingerprint, template ID, uint32 template version, template options including explicit false, copies, optional preview fingerprint, and optional schema. Preserve the original body bytes through the project-owned port and generated SDK's WithBody request; do not decode and re-encode explicit input or narrow its numbers.

Explicit JSON bypasses default-setting and printer lookups. Its expected media fingerprint and preview fingerprint remain the caller's concurrency checks. A printer test's body printer ID must match the positional destination. Reject malformed required fields, nonpositive or out-of-range numbers, and mixed JSON/selection flags before authentication. Server-specific template support, configured copy limits, and state-dependent validation remain authoritative. In particular, printer tests require one copy on the current server; the CLI never silently replaces a supplied copies value.

The existing flag/default selection flow remains available. Add `--expected-media-fingerprint` and `--preview-fingerprint` to the three submission commands. When an expected fingerprint is explicit, retain it instead of refreshing it from a printer lookup. Missing settings continue to come from inventory defaults, and omitted expected fingerprint comes from the selected printer. Named template versions preserve the server's full uint32 range without an int32 conversion. Test printing defaults to one copy but does not force one over a supplied value. Reject flags that do not apply to these requests, and reject a printer test flag that contradicts its positional destination.

Keep tenant/inventory scope, authentication, request correlation, existing response mapping, and print safety behavior. Explicit and generated idempotency keys are shown through the existing output notice and passed unchanged to the server. Permit key reuse with an unchanged explicit request; do not automatically retry a submission or fetch new data to repair a conflict.

Critical tests cover all three wire routes with complete exact input, 64-bit copies and uint32 versions, preserved false/null/preview/expected fingerprint fields, no hidden lookups, idempotency keys, safe authorization failures, conflict without retries, malformed input before authentication, mixed flags, and the existing default workflow. No API coverage, roadmap, or public documentation updates belong to this isolated batch.
