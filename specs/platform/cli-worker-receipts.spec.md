# CLI worker protocol receipts

The existing hardware-authoritative print worker exposes safe receipts for heartbeat, printer reports, claim (including no claim), start, renewal, outcome, reconciliation, idle confirmation, and verified artifact retrieval. It does not add manual commands that manufacture identities, claim proofs, device observations, or successful printing.

Receipts use a project-owned sealed result interface and an injected no-error ProtocolReceipts port. Successful API acknowledgements retain complete safe response fields, schema, metadata, nulls, and unsigned revisions. Credentials, claim tokens, request proofs, artifact bytes, and journal contents are excluded. Artifact receipts are emitted only after the worker validates size, digest, content type, and dimensions; they describe verified content, not successful hardware output.

Human output labels each operation and presents safe domain fields. JSON output emits one receipt envelope per line. A shared bounded queue and single background writer prevent receipt interleaving. Record never waits for output. Queue saturation disables receipts and drops queued receipts; the writer attempts one safe diagnostic when it becomes writable. Output failure likewise disables delivery. A bounded Close(context) drain is available to short-lived commands, outside worker mutation and hardware control paths. Delivery is best effort, not a durable event log; normalized typed results are not byte-identical server JSON. output errors never alter mutation results, cause retry, or reorder journal persistence and physical submission gates. Pairing workflows share the same sink with their own explicitly safe models.

Critical validation covers complete safe envelopes, null claims, unsigned revisions, unsuccessful requests producing no success receipt, sink failure without replay, and verified artifact receipt gating. Existing worker recovery and no-replay tests remain authoritative. No new dependencies or hardware policies are introduced.

The delivery queue holds at most 64 receipts. Closing delivery rejects new records and waits only until the supplied context ends; callers can distinguish a completed writer from a timed-out drain. Worker shutdown allows at most one second for this drain. A permanently blocked generic output writer can retain its one delivery goroutine until process exit, but cannot retain the worker execution path. Short-lived pairing commands must finish this drain before writing their final stdout result and suppress that final result if the writer remains blocked.

Validation: the full CLI suite passed on Linux on the dedicated remote validation checkout. Focused presentation and printworker race tests cover concurrent JSON records, output failure, a blocked writer with queue saturation, cancellation, and artifact verification. This does not claim physical-printer validation.
